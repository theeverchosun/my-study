WS(Web Server)와 WAS(Web Application Server)의 핵심 차이는 정적 콘텐츠 처리와 동적 애플리케이션 로직 수행에 있습니다.

### 웹 서버(Web Server)란

클라이언트(브라우저)의 요청을 받아 정적인 자원(HTML, CSS, JS, 이미지 등)을 응답해주는 서버입니다.

### WAS(Web Application Server)란

정적 자원뿐만 아니라 동적인 처리(DB 조회, 비즈니스 로직 실행 후 결과 생성)가 가능한 서버입니다.

- 내부에 **서블릿 컨테이너(Servlet Container)**를 가지고 있어 Servlet, JSP 코드를 실행할 수 있습니다.

구분           	  WS (Web Server)            	               WAS (Web Application Server)

역할         정적 컨텐츠 제공 (HTML, CSS, 이미지)           동적 컨텐츠 제공 (비즈니스 로직 연산, DB 조회)

작동 방식  클라이언트 요청을 받아 이미 있는 파일 전달	요청에 따라 코드를 실행하고 연산 결과를 생성해 전달

주요 기능   HTTP 요청/응답 처리, 리버스 프록시, 로드 밸런싱	웹 컨테이너/서블릿 컨테이너 구동, DB 연결 관리




Spring



**스프링(Spring)**은 **자바(Java) 기반의** 엔터프라이즈 애플리케이션을 쉽게 개발할 수 있도록 지원하는 **프레임워크**입니다. **POJO 기반으로 객체를 생성하고 관리**합니다.

**DI(의존성 주입)**, **AOP(관점 지향 프로그래밍)** 같은 핵심 기술을 바탕으로 **유지보수가 쉬운 애플리케이션**을 개발할 수 있도록 지원합니다.

스프링은 웹, 데이터, 보안, 트랜잭션 등 모든 계층의 기능을 통합적으로 제공하는 범용 프레임워크입니다.


특징

## POJO (Plain Old Java Object) 기반 개발

스프링은 특수한 클래스가 아닌 일반 자바 객체(POJO)로 비즈니스 로직을 작성할 수 있도록 합니다.

이는 **유연하고 테스트하기 쉬운 코드**를 지향하기 위함입니다.


## 제어의 역전(IoC: Inversion of Control)

객체의 생성 및 생명주기 관리 책임을 개발자가 아닌 **프레임워크에 위임**합니다.

이를 통해 애플리케이션 전체의 **구조적 일관성과 확장성**을 확보할 수 있습니다.

결합도를 낮추고 유연하며 테스트 가능한 코드를 만들기 위해 활용합니다.


## 의존성 주입(DI: Dependency Injection)

필요한 객체를 직접 생성하지 않고 **외부에서 주입받아 사용하는 방식**입니다.

**결합도는 낮추고 테스트 용이성을 극대화**합니다.


## 관점 지향 프로그래밍(AOP: Aspect-Oriented Programming)

공통적으로 반복되는 코드를 분리하여 별도로 관리하는 프로그래밍 방식입니다.

핵심 비즈니스 로직에 집중할 수 있도록 공통 기능(로그, 보안, 트랜잭션 등)을 분리하여 처리합니다.

이를 통해 코드의 **관심사 분리(Separation of Concerns)**를 실현합니다.
