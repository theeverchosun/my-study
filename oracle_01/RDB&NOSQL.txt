## 관계형 데이터베이스(RDB)

관계형 데이터베이스(RDB, Relational Database)는 데이터를 구획이 나뉜 '테이블(Table)' 형태로 저장하고, 이 테이블 간의 '관계'를 바탕으로 데이터를 관리하는 시스템입니다.

쉽게 비유하자면, "서로 유기적으로 연결된 거대한 엑셀 파일들의 집합"이라고 생각하시면 됩니다.

핵심구성요소
테이블(table)	데이터를 저장하는 기본 단위
행 (Row)	        하나의 레코드, 실제 데이터 1건
열 (Column)	데이터의 속성(항목)
기본키 (PK) 	각 행을 고유하게 식별하는 값
외래키 (FK) 	다른 테이블의 기본키를 참조하는 값

트랜잭션 보장 특성
A	원자성 (Atomicity)	작업은 전부 성공하거나 전부 실패, 중간 상태 없음
C	일관성 (Consistency)	트랜잭션 후에도 데이터의 유효성이 항상 유지됨
I	고립성 (Isolation)	동시에 실행되는 트랜잭션이 서로 영향을 주지 않음
D	지속성 (Durability)	커밋된 데이터는 시스템 장애가 발생해도 영구 보존


## NOSQL

RDB가 '규격화된 엑셀 파일'이라면, NoSQL(Not Only SQL)은 "정해진 틀 없이 데이터의 특성에 따라 자유롭게 저장하는 서류함"과 같습니다.

2000년대 후반, SNS와 스마트폰의 등장으로 대용량 비정형 데이터(텍스트, 이미지, 로그 등)가 폭발적으로 늘어나자, 엄격한 RDB의 한계를 극복하기 위해 태어난 데이터베이스 시스템입니다.

NoSQL의 4가지 주요 형태
NoSQL은 하나의 종류가 아니라, 데이터를 저장하는 방식에 따라 크게 4가지로 나뉩니다. 목적에 맞는 형태를 골라 사용합니다.

문서형 (Document) DB: 데이터를 JSON이나 XML 같은 문서 데이터 형식으로 저장합니다. 행마다 데이터 구조가 달라도 상관없어 가장 널리 쓰입니다.

예시: MongoDB, CouchDB

키-값 (Key-Value) DB: 이름 그대로 '키(Key)'와 '값(Value)'의 쌍으로만 데이터를 저장하는 가장 단순한 형태입니다. 속도가 압도적으로 빨라 캐싱(Caching)에 자주 쓰입니다.

예시: Redis, DynamoDB

와이드 컬럼 (Wide-Column) DB: 행마다 각기 다른 개수와 종류의 열(Column)을 가질 수 있는 구조입니다. 대용량 데이터의 읽기/쓰기 성능이 매우 뛰어납니다.

예시: Cassandra, HBase

그래프 (Graph) DB: 데이터 사이의 '관계(Link)'를 시각적인 그래프 형태로 저장합니다. SNS의 친구 추천, 내비게이션 경로 탐색 등에 특화되어 있습니다.

예시: Neo4j

장점

자유로운 구조 (Schema-less): 처음에 데이터 구조를 정해놓지 않아도 됩니다. 데이터 형태가 수시로 바뀌는 스타트업이나 신규 프로젝트에 유리합니다.

압도적인 수평 확장성 (Scale-out): 트래픽이 몰리면 저렴한 서버 여러 대를 붙여서 데이터를 분산 저장하기가 RDB보다 훨씬 쉽습니다.

빠른 속도: 복잡한 관계를 따지지 않고 데이터를 직관적으로 가져오기 때문에, 대용량 데이터를 빠르게 읽고 쓸 수 있습니다.

단점

데이터 중복 가능성: 데이터를 여러 군데 중복해서 저장하는 경우가 많아, 수정할 때 모든 곳을 다 변경해 주어야 하는 번거로움이 있습니다.

복잡한 쿼리의 어려움: RDB처럼 여러 테이블을 엮어서 분석하는 JOIN 연산이 기본적으로 불가능하거나 매우 까다롭습니다.

일관성 부족: 실시간으로 데이터가 딱딱 맞아떨어지기보다는, "시간이 지나면 결국 일치해진다(Eventual Consistency)"는 방식을 취하는 경우가 많아 금융 데이터 등에는 위험할 수 있습니다.



특징                         RDB                           NOSQL

데이터 구조       엄격한규칙                         유연한 구조

확장방식          서버성능키우기(SCALE UP)       서버 개수 늘리기 (SCALE OUT)

데이터관계     테이블간 JOIN 가능                관계없음 JOIN 어려움

적합한곳       금융 결제, 회원정보                 SNS 실시간 채팅등

RDB는 '정확성' 이 핵심, NoSQL은 '유연성과 속도' 가 핵심입니다.
