객체 지향 4대 특징

1. 상속

현실 세계에서 부모님이 자식에게 재산을 물려주듯, 프로그래밍에서는 **기존의 클래스(부모)가 가지고 있는 속성(필드)과 기능(메소드)을 새로운 클래스(자식)가 그대로 물려받는 것**을 말합니다.

-표현식
    - 자식 클래스 선언 시 `extends` 키워드를 사용합니다.

상속의 장점은

 적은 양의 코드로 새로운 클래스 작성 가능: 부모의 코드를 그대로 가져다 쓰므로 중복이 제거됩니다.
코드를 공통적으로 관리:부모 클래스 한 곳만 수정하면 이를 상속받은 모든 자식 클래스에 자동 반영되므로 유지보수가 매우 쉬워집니다.

상속에는 메소드 오버라이딩이 있는데

부모 클래스로부터 물려받은 메소드의 내용이 자식 클래스에 맞지 않을 때, 자식 클래스 내부에서 메소드를 재정의하여 덮어쓰는 기술입니다.

성립조건 : 부모 메소드와 이름 매개변수의 개수 타입순서 반환형이 같아야한다.

2. 다형성
"하나의 객체(참조변수)가 여러 가지 형태를 가질 수 있는 능력"을 뜻합니다. 자바에서는 부모 타입의 참조변수로 자식 타입의 인스턴스를 참조할 수 있도록 하여 다형성을 구현합니다.

다형성이 없다면 소나타 배열, 아반떼 배열을 따로 만들어야 하지만, 다형성을 활용하면 부모 타입의 배열 하나로 모든 자식 객체들을 묶어서 관리 할 수 있습니다.


Car[] carArr = new Car[5];

carArr[0] = new Sonata();
carArr[1] = new Avante();
carArr[2] = new Grandure();
carArr[3] = new Spark();
carArr[4] = new Morning();

3. 추상화

 간단히 복잡한 내부는 감추고 핵심적인 기능과 정보를 골라내어 단순화한것으로
잘사용하면 유지보수가 쉬워지고 코드의 복잡성을 줄여줍니다.

주로 추상 클래스(abstract)와 interface를 사용하는데

추상클래스는 클래스앞에 abstract를 넣어 사용하며 미완성상태이므로 객체생성(new)를 생성할수없습니다. 즉 반드시 자식클래스가 상속받아 사용해야합니다.

Interface는 추상클래스보다 보다 원시적인 형태로 프로그램 설계규격판 역할을 합니다.

그리고 다중 상속이 가능하며 자식클래스는 쓸때 implements를 사용합니다.


4.캡슐화

캡슐화(Encapsulation)는 객체지향 프로그래밍(OOP)의 핵심 개념 중 하나로, 쉽게 말해 "관련된 데이터와 기능을 하나의 알약(캡슐)에 담고, 내부가 보이지 않게 감싸는 것"을 말합니다.

캡슐화의 핵심은 두가지로 1) 데이터와 기능을 하나로 묶기 2)은닉화(Information Hiding) (내부 데이터를 외부에 함부로 보여주지 않고 숨기기)로

보통 클래스 부분에 private를 통해 객체를 은닉합니다.
